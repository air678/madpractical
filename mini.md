## **C. ChangeNotifier and State Management**

Your project uses ChangeNotifier state management.

**Q. What is state management?**

State management means managing changing data in an application and updating the UI when that data changes.

Example:

- User creates a project.
- Project progress changes.
- Project score is generated.
- The home screen needs to display updated information.

**Q. What is ChangeNotifier?**

ChangeNotifier is a Flutter/Dart class that notifies listening widgets when its data changes.

Simple example:

```
class Counter extends ChangeNotifier {
  int count = 0;

  void increase() {
    count++;
    notifyListeners();
  }
}
```

What happens?

1. Initially, count is 0.
2. The user presses the button.
3. Count becomes 1.
4. `notifyListeners()` informs the listening widgets.
5. The UI updates.

**Q. What is the difference between setState and ChangeNotifier?**

| setState                     | ChangeNotifier                      |
| ---------------------------- | ----------------------------------- |
| Used for local widget state  | Useful for shared application state |
| Simple to implement          | Better for shared state logic       |
| Rebuilds the relevant widget | Notifies listening widgets          |

For your viva, say:

"We use ChangeNotifier to manage application state and notify the UI whenever project data changes."

## **D. SharedPreferences**

**Q. What is SharedPreferences?**

SharedPreferences is a Flutter package used to store small amounts of data locally on the device in key-value format.

Your project uses it to store projects and settings as JSON.

For example:

```
Key: projects

Value:
[
  {
    "name": "CampusCrate",
    "stage": "Problem"
  }
]
```

**Q. Why did you use SharedPreferences?**

Because we wanted to store projects and application settings locally without requiring a cloud database.

**Q. What is the difference between SharedPreferences and Firebase?**

| SharedPreferences                    | Firebase                                        |
| ------------------------------------ | ----------------------------------------------- |
| Stores data locally                  | Stores data in cloud services                   |
| Data stays on that device            | Data can be accessed across devices when synced |
| Suitable for small settings and data | Suitable for larger backend requirements        |

**Important viva point:** Your presentation says that projects and settings stay on the phone. It does not describe a cloud database. So don't tell the examiner that you use Firebase.

## **E. HTTP**

**Q. What is HTTP?**

HTTP stands for Hypertext Transfer Protocol.

It is a communication protocol used to transfer information between a client and a server.

Your project uses the HTTP package to send requests to the Groq API.

**Q. What is the difference between GET and POST?**

- GET: Used to retrieve information.
- POST: Used to send information to a server.

For an AI generation request, your application sends a POST request containing the prompt and model details.

## **F. PDF, share_plus and path_provider**

These three are related to your project's report export feature.

**Q. What is the PDF package?**

It is used to generate PDF documents programmatically.

In PitchMate AI, it creates a designed report containing information such as the idea score, business canvas and roadmap.

**Q. What is share_plus?**

It allows an application to open the device's sharing interface.

For example, you can share your report through:

- WhatsApp

- Other supported apps

**Q. What is path_provider?**

It provides access to common device directories, such as temporary and application document directories.

It helps your application decide where to create or store a generated file.

**Remember these three:**

- path_provider = Find storage location.
- share_plus = Share report.

# **6. Business concepts used in PitchMate AI**

## **A. What is MVP?**

MVP stands for Minimum Viable Product.

It means creating the simplest working version of a product with only its most important features.

Example:

Suppose you want to create a book exchange app.

Your full application might have:

- Login
- Chat
- Payment
- Book exchange
- Reviews
- Notifications

But your first version might only have:

- Add a book
- View available books
- Contact the owner

That simple version is your MVP.

**Viva answer:** MVP is the simplest version of a product that contains enough essential features to test the idea with real users.

Business Model Canvas is a framework used to understand how a business works.

## **C. What is MoSCoW prioritisation?**

MoSCoW is a technique for deciding which features are most important.

It has four categories:

| Letter | Meaning            |
| ------ | ------------------ |
| M      | Must Have          |
| S      | Should Have        |
| C      | Could Have         |
| W      | Won't Have for now |

Example for your book exchange app:

- Must Have: Add and view books.
- Should Have: Search books.
- Could Have: User reviews.
- Won't Have for now: AI book recommendations.

**Q. Why do you use MoSCoW in PitchMate AI?**

To help students avoid building unnecessary features and focus on the most important features first.

## **D. What is a four-week roadmap?**

A roadmap is a plan that explains what should be developed and when.

For example:

| Week   | Work                     |
| ------ | ------------------------ |
| Week 1 | Design and basic setup   |
| Week 2 | Build essential features |
| Week 3 | Testing and improvements |
| Week 4 | Final demo preparation   |

Your application generates a four-week MVP roadmap to help students plan their development.

## **E. What is a competitor analysis?**

Competitor analysis means studying other businesses or applications that offer similar services.

It helps identify:

- What competitors provide.
- What they charge.
- Their strengths and weaknesses.
- What makes your idea different.
